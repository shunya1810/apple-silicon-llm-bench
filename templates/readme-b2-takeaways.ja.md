- **短いプロンプトでは Splash が速い。** 2K では、両モデルとも Splash が最速である（27B の 2〜3 ターン目の decode は 57 対 41 tok/s、A3B は 122〜127 対 111〜116）。Splash の DFlash2 の draft は 1 回の verify で 5〜6.6 トークン進む。MTP の深さ 3 では最大 4 トークンである（fork の 27B の 1 ラウンドは 25〜40% 短いが、進むのは 3.5 トークン）。メモリも、どの長さでも Splash が最も少ない（27B は 24〜33 GB、A3B は 26〜29 GB）。
- **長いプロンプトでは M1 fork が速い。** 8K から先では、両モデルとも fork のプロンプトの読み込みが最速で、差は長いほど開く。27B は Splash の 1.11 倍（8K）から 1.28 倍（128K）、A3B は 1.07 倍（8K）から 1.51 倍（128K）、1.57 倍（246K）である。decode も深い文脈で落ちにくい。27B は 64K で Splash と並び、128K から上回る（2〜3 ターン目: 27 対 25 と 17.5 tok/s、246K: 21 対 14）。A3B は 8K で並び、32K から上回る（32K: 97〜99 対 89〜92 tok/s、128K: 61〜64 対 49〜53、246K: 47〜49 対 34〜36）。Splash の 27B の decode は、32K から先で後半のターンほど落ちる（3 ターン目: 32K で 30 tok/s、64K で 23、128K で 17.5）。
- **MTPLX upstream 2.12.2 と比べると**（同じ重み、同じ引数）、fork はプロンプトの読み込みが 1.1〜1.9 倍、decode が 1.3〜4.4 倍速い（27B・128K: 25〜28 対 6 tok/s、A3B・246K: 47〜49 対 12〜13）。メモリも 32K から先は少ない。upstream は 27B の 246K を処理できなかった。
- **oMLX 0.7.1rc1** の decode は、upstream と fork の間にある。ただ 27B では毎ターン、プロンプト全体を読み直す（2 ターン目の応答開始は 2K で 13 秒、64K で 43 秒、128K で 24 分）うえ、M1 では KV が fp16 になる。A3B では 128K までプロンプトを再利用し（2 ターン目: 2〜20 秒）、246K では読み直す。
- **oMLX 独自の oQ4e 量子化**（補足の行、重みが違う）は、27B では共通の重みの oMLX とほぼ同じ速さで（decode の差は ±10% 前後）、A3B では遅い（読み込みは 0.5〜0.75 倍、decode は 0.8〜1.0 倍）。5〜6bit の層の分、読むデータが多いためである。品質はここでは測っていない。
