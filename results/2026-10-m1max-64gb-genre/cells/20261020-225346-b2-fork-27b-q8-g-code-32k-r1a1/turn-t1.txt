=====
`_markupbase.py` provides a `ParserBase` class that serves as the foundation for Python's HTML and XHTML parsers (specifically `html.parser`). It handles the low-level scanning of SGML/XML declaration constructs like `<!DOCTYPE ...>`, `<!-- ... -->` comments, and `<![...]]>` marked sections.

**Module-level regexes** define the matching patterns: `_declname_match` for identifiers, `_declstringlit_match` for quoted strings, `_commentclose` for `-->`, and `_markedsectionclose` for `]]>`.

**The `ParserBase` class** works as follows:

- `__init__` prevents direct instantiation, enforcing subclassing.
- `reset` and `getpos`/`updatepos` track the parser's current line number and column offset as data is consumed.
- `parse_declaration` is the main entry point for `<!` constructs. It dispatches to `parse_comment` (for `<!--`), `parse_marked_section` (for `<![`), or performs a character-by-character scan over the declaration body, handling nested names, string literals, and internal subsets (via `_parse_doctype_subset`). It returns the index past the closing `>` or `-1` if the buffer is incomplete.
- `parse_marked_section` handles both standard SGML status keywords (TEMP, CDATA, IGNORE, etc.) and the MS Office extensions (`if`, `else`, `endif`), using the appropriate close pattern.
- `parse_comment` locates the `-->` terminator.
- `_parse_doctype_subset` walks the internal subset of a DOCTYPE, recursively handling nested `<!ELEMENT`, `<!ATTLIST`, `<!ENTITY`, `<!NOTATION` declarations and parameter entity references (`%name;`).
- `_parse_doctype_element` and `_parse_doctype_attlist` are simpler scanners that skip past their respective declaration bodies.

Subclasses (like `html.parser.HTMLParser`) inherit from `ParserBase`, override the `handle_decl`, `handle_comment`, and `unknown_decl` callbacks, and set `rawdata` with the current input buffer. The base class thus isolates all the tedious position-tracking and state-machine logic, letting concrete parsers focus on semantic handling.
