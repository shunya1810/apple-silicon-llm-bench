=====
`_markupbase.py` provides shared support for scanning SGML/XML declarations in HTML and XHTML. It is an internal module used as a foundation by `html.parser` and has no public API.

**Module-level regexes** — Precompiled patterns (`_declname_match`, `_declstringlit_match`, `_commentclose`, `_markedsectionclose`, `_msmarkedsectionclose`) match names, string literals, comment closers, and marked-section closers (including the MS-Word variant).

**`ParserBase`** — The sole class, intended to be subclassed. Its methods:

- `__init__` raises `RuntimeError` if instantiated directly, enforcing subclassing.
- `reset` / `getpos` / `updatepos` — track the current line number and column offset as raw data chunks are consumed in order.
- `parse_declaration(i)` — the core dispatcher for `<!...>` constructs. After the `<!` prefix it branches: `--` routes to `parse_comment`, `[` routes to `parse_marked_section`, and otherwise it scans a name (e.g. `DOCTYPE`, `ELEMENT`, `ATTLIST`) then walks characters until the closing `>`, dispatching to `handle_decl` or `unknown_decl`.
- `parse_marked_section(i)` — handles `<![...]]>` sections. It recognizes standard status words (`TEMP`, `CDATA`, `IGNORE`, `INCLUDE`, `RCDATA`) with `]]>` closers, and MS-Word extensions (`if`, `else`, `endif`) with `]>` closers.
- `parse_comment(i)` — locates the `-->` closer and calls `handle_comment` with the body.
- `_parse_doctype_subset(i, declstartpos)` — parses the `[...]` internal subset of a DOCTYPE, recursively handling nested comments, parameter-entity references (`%name;`), and element/attlist/entity/notation declarations via `_parse_doctype_*` helpers.
- `_parse_doctype_element` / `_parse_doctype_attlist` — scan past the respective declaration bodies (the file is truncated mid-method).

Together these methods let a subclassing parser (like `HTMLParser`) correctly tokenize and dispatch all forms of `<!...>` markup while maintaining accurate position tracking.
